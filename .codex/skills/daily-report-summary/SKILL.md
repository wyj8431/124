# 今日开发日报

当用户要求“总结今日日报”“生成开发日报”或同步当天项目进度时使用。本 Skill 面向“灵图工坊”项目，输出简体中文 Markdown；不要用于周报、产品/市场报告，或没有项目证据的泛化总结。

## 使用流程

1. 确认项目根目录、当前本地日期和时区，读取项目根目录的 `AGENTS.md` 与 `DEVELOPMENT_SKILLS.md`。
2. 在项目根目录运行证据采集脚本：

   ```powershell
   & .codex\skills\daily-report-summary\scripts\collect_daily_evidence.ps1 -ProjectRoot .
   ```

   如需总结指定日期，可追加 `-Date '2026-08-25'`。脚本只读采集当天的 Git 提交、暂存区、工作区 diff 摘要和变更路径；输出只是候选证据，不能直接当成完成结论。
3. 将脚本输出与用户提供的工作记录、终端输出、测试/构建结果、接口响应和页面验收记录交叉核对。优先使用同时写明命令和实际结果的记录。
4. 按项目现有日报模板输出，日期使用本地 `YYYY-MM-DD`：

   ```md
   ## YYYY-MM-DD 开发日报

   ### 今日完成
   - 前端：
   - 后端：
   - 联调/文档：

   ### 验证结果
   - 命令或接口：
   - 结果：

   ### 风险与阻塞
   - 问题：
   - 影响：
   - 所需支持：

   ### 下一步
   1.
   2.
   3.
   ```

## 事实边界

- 只总结当天发生且有证据支撑的工作；跨天旧记录要注明原日期，不能混入“今日完成”。
- 当天 commit 只能证明代码变更存在，不能推断测试或验收通过。
- 只出现在 `git status` 中的未提交文件只能写成“工作区候选改动”；没有明确验收记录时不得写成已完成。
- 没有观察到的测试、构建、接口或页面结果必须写“未执行”或“未验证”，不能补写“通过”。
- 文件和接口使用仓库中的实际路径或端点；按前端、后端、联调、文档归类，避免逐文件罗列无关改动。
- “风险与阻塞”只列真实错误、缺失依赖、未完成验收及影响范围，不要把普通待办包装成故障。
- “下一步”最多 3 项，按优先级给出可执行动作，并从已识别风险或未完成验收推导。
- 如果证据不足，仍输出日报，并在“风险与阻塞”明确写“今日可确认记录不足”，列出需要补充的工作记录或验证结果。
